# Simplification audit — September 15, 2026

This is the original proposal against `47a35e8`. All 28 candidates have since been implemented at the user’s request, with performance measurements deferred until the machine is quiet. See [implementation results](simplification-results.md) for commits and validation. Source references below identify files as they existed at the baseline; some declarations have since been removed.

Reviewed commit `47a35e8` (`Consolidate shared Cargo workspace settings`). The tree contains 120 tracked Rust files, about 48,000 Rust lines, and 558 shell tests. This audit covers the workspace structure, input pipeline, command-line parser, core linker passes, ELF representations, architecture implementations, output handling, utilities, and test runner. The pre-existing untracked `gentoo/` directory and build artifacts were excluded.

The best opportunities remove unused bookkeeping or share existing operations while preserving data layout, allocation patterns, and scheduling. There are **28 candidates below: six small deletions, fifteen structural or maintenance changes, and seven experiments that need performance measurements before adoption**. The experiments are possibilities, not claims of acceptable performance. The original audit was a source review; no implementation changes, test runs, or new benchmarks were made during that review.

I would start with items 1–6, then 7–10 and 15. The unused priority registry is the clearest simplification across several modules. The header-only section types and repeated chunk accessors offer a larger reduction in boilerplate. File collection can then be simplified without changing command-line ordering.

The first six changes have a direct deletion argument and do not require replacing a performance-sensitive algorithm. Public API removals below assume the workspace's current consumers; an external consumer of the `mold` library could still make them source-incompatible.

1. **Delete the unused architecture metadata registry.** [TargetInfo and arch::TARGETS](../src/arch/mod.rs) describe twenty architectures in approximately 130 lines, but repository-wide searches find no consumers. Target detection and emulation selection use other code. Delete both declarations. The separate `TARGETS` constants in the CLI and test runner are used and have different purposes. Expected runtime cost: none.

2. **Delete `Context::file_by_priority` and the DSO keep mask.** The [context field](../src/context.rs) is maintained by the [reader](../src/reader.rs), [DSO deduplication](../src/driver.rs), [internal-object creation](../src/passes.rs), and [LTO output loading](../src/lto.rs). Its stored IDs serve only its own bookkeeping; actual [symbol resolution](../src/passes.rs) builds a file list from `objs` and `dsos`. The reader uses its length to assign priorities, which can instead use `pending.into_iter().enumerate()` and `10000 + i`. Preserve internal priority 0, LTO priorities beginning at 100, and priority gaps after deduplication. Then retain DSOs directly with `dso_sonames.insert(file.soname)`, eliminating the temporary `keep` vector and registry cleanup loop. Keep discarded files in `FileList`'s backing pool so previously recorded symbol pointers remain valid. Expected runtime effect: less allocation and bookkeeping.

3. **Remove the vestigial script callback from machine detection.** All three callers of [filetype::get_machine_type](../src/filetype.rs) pass `|| None`. The [reader](../src/reader.rs) already handles linker scripts separately. Remove the callback parameter and make the text case return `None`. Preserve detection's native-input-before-script precedence. This removes an abstraction with no current variation and should leave generated work unchanged.

4. **Delete unused helper methods.** [Symbol::output_chunk](../src/symbol.rs), [Endian::read_i16](../src/util/endian.rs), and [Endian::write_i16](../src/util/endian.rs) have no repository callers. Remove these methods rather than maintain speculative APIs. Check each generated endian helper separately; this finding does not imply all signed helpers are unused. Expected runtime cost: none.

5. **Keep parser-only settings out of the final `Args`.** The [argument representation](../src/cmdline.rs) retains `be8`, `color_diagnostics`, `demangle`, `fatal_warnings`, `noinhibit_exec`, `suppress_warnings`, and `directory`, although their member accesses are confined to parsing. Use locals for `be8` and `directory`; update diagnostic globals directly for the other settings. Preserve the [initial reset](../src/cmdline.rs) and immediate encounter-order changes, since diagnostics during parsing observe them. This deletes fields, default initializers, and duplicate assignments without changing linking work.

6. **Remove two redundant pieces of state.** [Context::page_size](../src/context.rs) copies `args.page_size` during construction and is never independently changed; read the argument field directly. [Glob::is_empty](../src/util/glob.rs) can be derived from `max_value < 0`, since the builder starts at -1 and accepts nonnegative values. Retain the method and the builder's nonnegative-value contract, including its behavior when a malformed pattern has been submitted. These remove invariants rather than algorithms.

The next fifteen changes need implementation review for behavior preservation. Their performance case depends on retaining the existing operations and representations, not on accepting slower replacements.

7. **Replace nineteen header-only section wrappers with `ChunkHeader<E>`.** Examples are [EhFrameSection](../src/chunks/eh_frame.rs), [InterpSection](../src/chunks/interp.rs), and [OutputEhdr](../src/chunks/mod.rs). The complete set is `EhFrameSection`, `InterpSection`, `RelPltSection`, `SFrameRelocSection`, `DynamicSection`, `NotePackageSection`, `StrtabSection`, `Ppc64SaveRestoreSection`, `HashSection`, `RelroPaddingSection`, `OutputEhdr`, `OutputShdr`, `GdbIndexSection`, `RelrDynSection`, `SymtabSection`, `EhFrameRelocSection`, `ShstrtabSection`, `GotPltSection`, and `SymtabShndxSection`. Each contains only `hdr`. Keep named, section-specific header constructors to preserve flags and alignment, and keep data-bearing section types. Operations mostly already live in module functions. This trades nominal type distinctions for fewer types and `.hdr` layers; it needs no dynamic dispatch or new allocation.

8. **Declare chunk-header access mappings once.** [chunk_header](../src/context.rs) and [chunk_header_mut](../src/context.rs) repeat essentially the same large match, including optional sections and indexed sections. A small explicit declaration can generate both accessors with static matches. Do this after item 7. Consider sharing related [chunk dispatch](../src/chunks/mod.rs) only where it actually removes repetition; multi-output writers and special cases should stay explicit. Avoid a large macro language or a trait-object registry. The intended result preserves static dispatch and existing field access.

9. **Generate paired ELF accessor implementations.** The 32/64-bit [PhdrRecord implementations](../src/elf.rs), [SymbolRecord implementations](../src/elf.rs), and [ChdrRecord implementations](../src/elf.rs) repeat field getters and setters. A small macro can emit each pair, including the differing integer types. Keep the actual `repr(C)` ELF structs, field ordering, and layout assertions distinct: the on-disk layouts are not interchangeable. This can reduce mechanical duplication without changing the generated accessors.

10. **Factor the repeated worker-bin and worker-cache pattern.** [Symbol bins](../src/context.rs), [reader result bins](../src/reader.rs), and caches in [COMDAT processing](../src/passes.rs), [merged-section processing](../src/passes.rs), and [output-section creation](../src/passes.rs) repeat worker indexing, fallback handling, mutex access, and collection. A small worker-storage helper could own these operations. Preserve padding where used, the main-thread fallback, cache reuse per actual worker, and lock frequency. Rayon `map_init` initializes per job, so it is not automatically equivalent. Removing locks through unsafe thread-local access would undermine the simplification.

11. **Use a small typed helper for background jobs.** The [driver's background wait](../src/driver.rs) and GDB/nonallocated-merge jobs repeat a bounded channel, Rayon spawn, send, and join pattern. A `Background<T>` helper could centralize that lifecycle while keeping timers, ownership, and job labels visible at call sites. Preserve cooperative `rayon::yield_now()` while waiting: a blocking receive can deadlock a one-thread pool. Keep the GDB worker limit and overlap with foreground passes. This should alter plumbing, not scheduling.

12. **Simplify option parsing incrementally.** [parse_args](../src/cmdline.rs) spans roughly 1,160 lines; its matching macros mutate shared cursor and argument variables. Start with a cursor helper returning borrowed `OsStr` values, a small declaration for plain positive/negative flags, and the repetitive [LTO forwarding cases](../src/cmdline.rs). Keep side-effectful options explicit. Preserve raw filename bytes, single/double-dash matching, attached and optional values, aliases, repeated options, and push/pop state. Do not casually normalize flags into enums: `shared` and `pie` can coexist, and `icf_all` currently has sticky behavior across repeated ICF options. Parsing is a cold path, but compatibility is substantial; a wholesale parser-library migration has a worse risk/reward balance.

13. **Share nonallocated-relocation preparation across backends.** [PPC64 ELFv1](../src/arch/ppc64v1.rs), [PPC64 ELFv2](../src/arch/ppc64v2.rs), [SPARC64](../src/arch/sparc64.rs), [ARM64](../src/arch/arm64.rs), and several other backends repeat symbol lookup, fragment resolution, addend calculation, location selection, and tombstone handling before their relocation switches. Extract a narrow generic helper or callback for the common preparation. Leave ISA switches, overflow checks, REL/RELA differences, and unusual stored-addend behavior local. Preserve the richer cached path in x86-64. This is hot code: adoption should require inlining/code-generation inspection and relocation-heavy measurements even though the proposed operations are unchanged.

14. **Share emitted-relocation symbol/addend mapping.** [Ordinary relocations](../src/chunks/reloc.rs), [.eh_frame relocations](../src/chunks/eh_frame_reloc.rs), and [.sframe relocations](../src/chunks/sframe_reloc.rs) repeat the mapping of section symbols to output-section indices and offsets, and ordinary symbols to output-symbol indices. Extract that common mapping. Keep ordinary merged/dead-section handling and `.eh_frame` REL addend patching separate. Scope validation to relocatable output and emitted relocations, including relaxation. A helper should preserve the same arithmetic and lookups.

15. **Assign input-file IDs once, after sorting owned results.** The reader already has an owned [Loaded enum](../src/reader.rs), but [push_loaded](../src/reader.rs) assigns provisional IDs. Later [final ordering](../src/reader.rs) takes both file lists apart into vectors of optional boxes, sorts `(position, FileId)` records, and rebuilds the lists with final IDs. Keep owned pending results until sorting and assign final IDs/priorities once. Preserve boxed storage, script processing order, and serial LTO claims in command-line order; verify plugin callbacks do not require early list membership. This should remove temporary containers and a state transition. Item 2 makes the change easier.

16. **Return an iterator for serial recursive archive traversal.** [read_archive_members](../src/archive_file.rs) eagerly collects a vector that its sole caller, [read_file](../src/reader.rs), immediately traverses once. Expose a common iterator over member views instead. Preserve archive positions, dependency registration, and acceptable diagnostic ordering for malformed inputs. The parallel reader deliberately schedules thin-member opening inside workers; leave that separate path parallel. This removes an intermediate allocation without sacrificing that scheduling.

17. **Represent valid output-backend states directly, if the result is shorter.** [OutputFile](../src/output_file.rs) combines `Storage` with `Option<File>`, forcing repeated cross-field matches and an impossible mapped-without-file branch. An enum that places the file with its backend could remove those invariants. However, [open_locked](../src/output_file.rs) intentionally creates a real file with an empty memory buffer before mapping it, so that staging state must remain representable. Preserve map growth, reservation, permissions, publishing, and locking. This is lower priority: abandon it if a new state machine requires more code than the current representation.

18. **Separate final statistics from event counters.** [show_stats](../src/passes.rs) creates many static counters and performs zero increments just to register names, even though it computes those quantities at the end from existing state. Build a local statistics snapshot and combine it with counters that genuinely record events during passes. Keep name registration, zero-valued output, and sorting behavior. The normal linking path is unaffected; this reduces machinery in the optional reporting path.

19. **Reuse the existing report writer for dependency output.** [write_dependency_file](../src/passes.rs) implements its own stdout/file handling and constructs the entire output byte vector. [ReportOutput::with_writer](../src/cmdline.rs) already centralizes buffered output and error handling. Reuse it and stream the two dependency-output passes over the ordered dependency list. Preserve raw path bytes, first-seen order, and stdout/file error semantics; using hash-set iteration would lose ordering. Exact failure-message wording may need adjustment in the helper to retain compatibility. This is an optional-output cleanup, not a reason to add an ordered-set dependency.

20. **Reduce accidental public API and remove stale explanations.** [lib.rs](../src/lib.rs) exposes almost every implementation module. Workspace entry points are the driver and architecture types; use crate visibility where possible while retaining types required by the public architecture interface. This lets compiler dead-code checks catch more abandoned helpers. Separately, [lto.rs](../src/lto.rs) explains the same LTO sequence twice, [file-removal comments](../src/passes.rs) still claim IDs are renumbered, and [finish_output documentation](../src/arch/mod.rs) mentions an ENDBR operation handled elsewhere in the driver. Correct these locally. Avoid large file moves or documentation deletion that removes the reasoning for optimizations.

21. **Flatten test-process error handling.** [run_job](../tests/lib.rs) nests log creation, descriptor cloning, spawn, and wait handling. A helper returning `Result<Outcome, ...>` can leave cleanup and status-file writing in one outer path. The descriptor-clone error currently returns early and skips status-file writing, so repairing that is a small intentional error-path behavior change. Preserve process-group timeout cleanup and detection of the shell tests' `skipped` line. Keep the already-simple scoped-thread scheduling and upstream-compatible shell tests. Linker performance is unaffected.

The remaining seven candidates deliberately trade a specialized implementation for a simpler one. None should be presented as performance-neutral before measurement.

22. **Replace `CieHandle` pointers with file/record indices.** [CieHandle](../src/chunks/eh_frame.rs) uses two raw pointers and roughly sixty lines of lifetime, aliasing, and mutation plumbing. An `(ObjId, cie_index)` handle could resolve immutable records through the context for comparison, then mutate the indexed record afterward. It may also make the similar leader searches in `.eh_frame` layout and [ICF](../src/icf.rs) shareable. Cost: extra indexed access in deduplication. Measure exception-heavy C++ and ICF links, including many distinct CIEs; verify GC, relocation, and exception behavior.

23. **Replace the custom mutable Rayon producer with a collected reference list.** [FileList's mutable iterator and producer](../src/input_files.rs) support indexed parallel traversal through live indices over stable boxed storage. Collecting the existing safe mutable iterator into `Vec<&mut T>` and then using its standard parallel iterator could remove much of the custom producer plumbing. Cost: one allocation and approximately eight bytes per live file on a 64-bit host each time the adapter is constructed. Benchmark many-file links and repeated mutable passes at one and many threads. Preserve stable storage and indexed ordering; scanning all dead backing entries is not an equivalent replacement.

24. **Return owned per-file output-section groups.** [OutputSectionBuilder](../src/passes.rs) allocates a dense array of per-file contributions for each output section and shares it through `Arc` and `UnsafeCell`. Returning each file's groups from the parallel pass, then combining them deterministically, could remove shared mutation and avoid dense empty slots. Cost: possible extra grouping and serial merging; the current flattening is parallel. Preserve persistent lookup caches and parallel bulk copying. Measure many files, many output sections, and Chrome-sized input-section counts before adopting this substantial refactor.

25. **Use the concurrent map's existing handles for GDB names.** [NameEntryRef](../src/gdb_index.rs) adds a GDB-specific raw-pointer wrapper. The [interning call](../src/gdb_index.rs) already receives an `EntryId` and discards it. Retain that ID and resolve it through the frozen map, or reuse the map's existing reference wrapper if it fits the phase lifetimes. Cost for IDs: additional lookup/address calculation in a path with millions of names. Preserve the compact `NameRecord` layout and deterministic pool ordering. Benchmark GDB indexing separately; this does not justify replacing the compact name-record union with a larger enum.

26. **Try static bounded chunks for the GDB worker helper.** [limited_parallel_for_mut_init](../src/gdb_index.rs) maintains a mutex-protected queue of roughly twice as many chunks as workers. A bounded number of static `par_chunks_mut` tasks could remove the queue and loop while retaining a maximum parallelism level. Cost: worse balancing for uneven compilation units or name counts, and potentially different scratch-state reuse. Keep the worker cap that protects foreground linking. Compare uneven DWARF workloads and one-thread operation; retain the current helper if imbalance exceeds any simplification benefit.

27. **Try `memchr` for bounded NUL searches.** [cstr_at](../src/util/mod.rs) selects between unsafe `strlen` and `strnlen`; the [GDB reader](../src/gdb_index.rs) also uses a bounded C scan. The existing `memchr` dependency can express safe searches directly. Preserve each caller's distinct missing-terminator behavior. Cost: potentially different SIMD dispatch and short/long-string behavior in a very hot path. Measure large symbol tables, long names, and debug input; do not assume a simpler Rust expression outperforms libc.

28. **Use one zlib implementation for compression and decompression.** [Cargo.toml](../Cargo.toml) includes both `flate2` and `libz-sys`. The installed, locked `flate2` 1.1.10 currently enables its Rust backend; an offline feature-tree inspection confirmed active `miniz_oxide`. Configuring `flate2` with `default-features = false, features = ["zlib"]` could reuse the native zlib implementation already used by the [parallel compressor](../src/util/compress.rs), removing the extra backend dependency subtree. Cost: decompression speed and malformed-input error behavior may change. Benchmark compressed debug input and prefix reads. Retain the specialized parallel encoder and its compatibility workaround; switching the decoder backend does not replace them.

Several tempting changes should stay out of the initial simplification work:

- **Keep the architecture crates.** [Cargo.toml](../Cargo.toml) explains why all twenty targets are instantiated in separate crates: combining them serializes expensive compilation. Their small wrappers buy build parallelism.
- **Keep compact symbols and stable ownership.** The 48-byte symbol representation, dense IDs, lazily allocated auxiliary state, boxed file storage, and process-lifetime input storage serve large input counts. Replacing them with larger general-purpose enums, per-record ownership objects, or pervasive reference counting can cost substantially more memory and cache traffic.
- **Keep specialized concurrent tables and worker caches.** The concurrent map, sizing estimates, ICF digest table, and persistent caches avoid contention and repeated work. A single locked standard map or per-task cache is not a low-risk simplification.
- **Keep the I/O and scheduling optimizations.** Small-file reads versus mappings, huge-page advice, filesystem-aware preallocation, output-map growth, background GDB/merge work, parallel scatter, and quick exit have explicit performance rationales. Simplifying them requires a separate performance case.
- **Keep the fast glob paths unless measurements support deletion.** [Glob](../src/util/glob.rs) has literal, prefix, suffix, automaton, and NFA paths. Although some automaton functionality overlaps the literal paths, its comment explains why common version-script patterns bypass full-string scans. Routing everything through one engine is likely to penalize common inputs; retain item 6's simple state deletion without redesigning matching.
- **Do not zero the full GDB output buffer merely to remove uninitialized allocation.** [build_tables](../src/gdb_index.rs) avoids an extra initialization pass over potentially large output. A zeroed buffer would still leave arbitrary-offset parallel scatter to justify, while adding memory traffic. A narrower lifetime-aware scatter wrapper may help, but it does not remove that underlying proof obligation.
- **Keep compatibility branches that still support inputs.** Older LTO interfaces, the zlib/libbacktrace workaround, endian-specific layouts, non-UTF-8 paths, and ISA-specific relocation exceptions are supported behavior. Deleting them requires a scope change, not just a refactor.

For implementation, use small independent patches so any slowdown can be attributed and reverted. Start with deletions, then header representation and dispatch, paired accessors, worker storage, and the reader's owned pending results. Take parser and relocation changes separately. Leave the seven experiments until the easier reductions are complete.

A practical provisional interpretation of “without impacting performance that much” is no more than a 1–2% geometric-mean slowdown, no repeatable regression above 5% on a representative workload, and no material peak-memory increase. Those are proposed acceptance limits, not measured results or requirements supplied by the user. A result within measurement noise should be reported as inconclusive rather than rounded into a win.

For performance validation, compare each candidate with a fresh build of the pinned baseline using the same compiler, release profile, and all-target configuration. The existing [performance report](../docs/upstream-sync-performance.md) supplies a useful workload list and protocol, but measures an older revision and cannot validate these proposals. The local `~/bench` response files provide representative Chrome x86-64/ARM64, TensorFlow, Clang, Godot, and other inputs. Use separate output files, warm-ups, rotated baseline/candidate order, several measured rounds, and a quiet host. Compare one and 32 threads for concurrency changes; include small links, large debug/release links, GDB indexing, and compressed input as applicable. Record elapsed time, CPU time, and peak RSS. Use the existing `--no-fork` protocol consistently, with a separate default-mode check when exit behavior matters.

For correctness validation after implementation, build every architecture instantiation and run the applicable existing unit and shell suites, including available cross-toolchain tests. Reader changes particularly need archive/script ordering, as-needed DSOs, duplicate sonames, LTO claim order, and COMDAT coverage. Parser changes need raw paths, repeated/negated options, and diagnostic ordering. Relocation and CIE changes need `-r`, `--emit-relocs`, GC, ICF, exceptions, and relaxation. GDB and compression changes need the existing determinism, DWARF-format, compressed-debug-input, and compressed-output tests. Add focused tests only for behavior gaps exposed by a refactor; the audit itself does not require new tests.
